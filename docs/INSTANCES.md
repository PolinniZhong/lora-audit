## 实例 01 · 审自己的 47 张训练集：1 条误报 → 加豁免机制

**日期**：2026-09-20 ｜ **数据**：自有角色的 LoRA 训练集（47 张、双 caption profile、分层 val=5；
由本项目的训练集构建器确定性产出，构建器会在同一次构建里写出豁免声明——理由见下）

### before

```
图片  47 张 · 逐图 caption 47 · default 兜底 0 · 无 caption 0 · 分组 3
结果  0 错误 · 2 警告
  ! W008 分辨率不统一（1773×2364 · 41 张, 2048×2048 · 6 张）
  ! W010 混入了系统杂物文件（.DS_Store ×2）
```

### 人工判定：1 条真、1 条误报

| 规则 | 判定 | 依据 |
|---|---|---|
| `W010` `.DS_Store` | **真问题** | 不该出现在要发布/打包的数据集里 |
| `W008` 分辨率不统一 | **误报** | 那 6 张 2048×2048 是**方形细节特写**；与标准格 1773×2364 并存是**分桶训练的既定设计**，不是混入了来源不同的图 |

**关键点**：`W008` 的告警文案本身就写着"如果这不是你有意为之"——**它承认自己可能是误报，但用户没有任何地方能说"我就是有意的"。** 这就是缺口。

### 因此改了什么（三层，缺一层这个实例就不成立）

1. **工具层**：新增可选的 `.lora-audit-ignore` 声明——用户终于有地方说"我知道，是有意的"。
   **设计红线：豁免 ≠ 隐藏。** 被豁免的规则**降级为 `info`**、标题标注「已豁免」、理由原样展示，
   摘要行也会出现「已豁免 W008」。**静默隐藏会变成自欺，审计工具最不能干的就是这个。**
2. **生成器层**：`kit_trainset.py --build` **自己写**这份声明（它知道方形图是有意的），
   并在构建后清掉系统杂物。为什么不能让用户手写：数据集是**派生物**，人工写的声明会被下次构建抹掉。
3. **规范层**：豁免的写法与红线写进 README。

### after

```
结果  0 错误 · 0 警告
  · W008 分辨率不统一（已豁免）
  · I001 识别到的布局    · I002 分组分布    · I003 触发词
```

报告页摘要行显示「已豁免 W008」，`W008` 卡片仍在、带豁免理由——**问题没有消失，只是被标记为已知**。

### 这个实例证明了什么、没证明什么

- ✅ **证明了**：工具在真实数据上被真实使用，报出的问题**被人复核、判定，并驱动了一次真实的工具改进**（工具 / 生成器 / 规范三层）
- ✅ 暴露了一条设计缺口（用户无法表达"有意为之"）并已补上
- ❌ **没有证明「它帮别人发现了问题」**——那仍是最缺的一类（见下表）

### 诚实标注

`W010` 的消失有一半是"重建时清空目录"的顺带结果。Finder 之后还会再生成 `.DS_Store`，
**届时这条警告会再次出现——这是正确行为，不豁免它。**

## 待补的实例类型

| 类型 | 现状 | 从哪来 |
|---|---|---|
| 自己用、并改进了工具 | ✅ **实例 01** | — |
| **帮别人发现并修复问题**（外部主体，最硬） | ❌ 零 | 拿工具去扫公开仓里的真实数据集，把结论反馈给作者 |
| **对比数据（抽卡 vs 资产管线）** | ✅ **已完成**（三组对照 ＋ 一次改进实验，共 **210 个独立样本**） | 复现验证方案的三组对照（定稿母版 / 跑崩图 / 无参考图） |
| 别人主动接了你的工具 | ❌ 零 | 只能等发布之后 |

> **发布时的判断**：要求是"至少还要一条**外部主体的**（帮别人发现）或一条**对比数据的**"。
> **「对比数据」这一条已满足**——三组参考图对照（定稿母版 / 跑崩图 / 无参考图）＋ 一次提示词改进实验，共 **210 个独立样本**。
> **「外部主体」与「别人主动采用」仍为零**：前者要拿工具去扫公开仓里的真实数据集并把结论反馈给作者，
> 后者只能等发布之后。**所以下面这两条仍然是这个项目最该去打的数。**
