# lora-audit 设计文档（SDD）v0.1

> **受众**：想读代码、想提 PR、想判断"这东西的工程判断靠不靠谱"的人。
> **不写**：怎么用（见 [README](../README.md)）；要什么、给谁、不做什么（见 [PRD](PRD.md)）。
> 本文所有数字都可复现，命令见 §10。

**一句话架构**：把一个训练文件夹变成一份**可自证的只读报告**——一个纯函数，零依赖，产物即应用。

---

## 1. 六条不可妥协的约束

先立边界，再看决策——下面每一条都在约束里出现过，不是事后总结。

| # | 约束 | 落地形式 |
|---|---|---|
| C1 | **零必需依赖** | `pyproject.toml` 的 `dependencies = []`，只用标准库 |
| C2 | **不起服务、不建索引、不写数据库** | 没有端口、没有后台进程；`scan` 是一次性遍历 |
| C3 | **不修改输入** | 全仓只有 **2 处**写文件（`cli.py` 的报告与可选 JSON），都在 `-o` 指定路径下 |
| C4 | **产物离线自足** | 零远程资源、零 `type="module"`、零 `fetch`/XHR |
| C5 | **产物是单个文件** | CSS / JS / 数据全部内联，用户拿到的是一个能双击、能发出去的东西 |
| C6 | **用户数据永不被当作 HTML** | 只走 `textContent` / `createElement`，不拼 `innerHTML` |

## 2. 决策表：选了什么、否决了什么、代价是什么

被否掉的选项比选中的更能说明问题。

| # | 决策 | 否掉的选项 | 为什么 | 代价 |
|---|---|---|---|---|
| D1 | 产物是**单个自包含 HTML** | `index.html + css/ + js/` 目录树 | 用户要的是能双击、能发微信、能丢进 issue 的东西；目录树拷漏一个文件就白屏 | 产物 47–63 KB；改样式要重新生成 |
| D2 | 图片走**相对路径引原图** | base64 内联 / 构建期缩略图 | 零拷贝、秒出、离线可用；内联需要 Pillow 且产物膨胀 | 报告**不能单独挪走**（`verify` 会报，页面降级显示"图片读不出来"） |
| D3 | **纯标准库** | 依赖 Pillow（只为读宽高） | 只想 `pip install` 一下的用户不该背一个 C 扩展；审计只需读文件 + 正则 + 写 HTML | 自己维护 5 种图片头解析器；**没有缩略图能力** |
| D4 | **输入契约为零**：不读任何配置文件 | 要求 manifest / 声明文件 | 社区主流是"先把图糊进一个文件夹"；要求对方先按我们的规范整理是方向反了 | 无从得知用户"意图"；分组只能靠目录结构推断 |
| D5 | **不起服务** | 本地 server + 实时索引 | 静态产物足够回答"这批图有没有问题"；服务化会杀死"双击即开" | 无多人协作、无实时更新、无语义搜索（明确非目标） |
| D6 | **自写约 70 行灯箱**，不内联第三方 | 内联 GLightbox（MIT） | 其 min 文件**没有 license banner**；内联进单文件产物 = 公开仓里多一段无署名的第三方压缩码 | 功能少（无画廊滑动/缩放），自己维护 |
| D7 | `scan` **不做判断**、`rules` **不碰文件系统** | 扫描时顺手判断 | 规则成了纯函数，可单独单测——35 个用例全部用合成夹具，不依赖任何真实图片库 | 多一层数据结构（`Dataset` / `ImageEntry`），多一个模块 |
| D8 | `verify` 是**独立子命令**，只读产物 | 把检查塞进 build | 产物应可被第三方检查；检查逻辑不该依赖生成逻辑 | 两边模式要同步（由测试兜住） |
| D9 | 规则**宁可少报也不误报** | 尽量多报 | 告警一旦有噪声，用户下次就不看了 | 小数据集上可能漏报（见 §6） |
| D10 | 主题切换**不持久化** | 写 `localStorage` | `file://` 下 localStorage 行为跨浏览器不一致；只读页面不该留状态 | 每次打开回到深色 |
| D11 | 大列表**不用** `content-visibility: auto` | 用（"大列表要虚拟化"的通用建议） | 它与 `img loading="lazy"` 相互作用会把并行加载**串行化**——同类瓦片页面上实测约 **10 倍**差距（3.2s → 0.3s） | 超大列表需别的手段；当前靠"超过 400 张才分批渲染"兜住 |
| D12 | 规则条目带 **`kind`**（`image` / `file` / `none`） | 只看 `items` 有没有内容 | 有些规则的条目是**路径不是图片**（杂物文件、孤儿 caption），拿它们筛图只会得到空网格 | payload 多一个字段，前端多一条分支 |
| D13 | 内联 JSON 做 `</` → `<\/` 转义 | 直接塞 JSON | caption 里完全可能出现 `</script>`，会把数据块**提前截断** | `verify` 要反向解码一次（已实现） |
| D14 | 加 `data:,` 空 favicon | 不管 | `file://` 页面没有图标时 Chrome 会去请求 `favicon.ico`，留下一条 `ERR_FILE_NOT_FOUND`——这条噪声会掩盖真正该看的问题 | 无 |

## 3. 模块边界

| 模块 | 行数 | 职责 | **明确不做** |
|---|---|---|---|
| `imagesize.py` | 178 | 读 PNG/JPEG/GIF/BMP/WebP 的文件头取宽高 | 不解码像素；**任何不确定返回 `None`，永不抛异常** |
| `scan.py` | 352 | 遍历文件夹，如实记录"这里有什么" | **不做任何判断、不打分**；不写文件 |
| `rules.py` | 356 | 把事实变成 findings | **不碰文件系统**（输入 `Dataset`，输出 `list[Finding]`） |
| `report.py` | 183 | 渲染单个自包含 HTML | 不含任何业务规则 |
| `static/report.css` | 468 | 报告页样式（令牌层 + 组件） | 不写死颜色，只用 `--alc-*` 令牌 |
| `static/report.js` | 444 | 渲染、筛选、搜索、抽屉、灯箱 | 不 fetch、不请求远程、不拼 `innerHTML` |
| `cli.py` | 235 | 参数、退出码、终端摘要、`verify` | 不含规则 |
| `tests/test_smoke.py` | 342 | 20 个端到端用例（含 `--json -` 的 stdout 纯净性） | 不依赖 pytest |
| `tests/test_layouts.py` | 216 | 15 个**真实目录布局**夹具（kohya 平铺 / `N_名称` 重复目录 / ai-toolkit / `.caption` / 元文件 / 扩展名误标） | 不下载第三方数据 |
| `tools/browser_check.mjs` | 315 | CDP 驱动真实 Chrome，15 个断言点 | 不引第三方依赖（用 Node 内置 WebSocket） |
| `examples/make_example.py` | 110 | 用标准库现写 PNG，造一份带已知缺陷的数据集 | 不依赖 Pillow |

**最关键的一条边界是 D7**：正因为 `scan` 不做判断、`rules` 不碰文件系统，规则才能被穷举测试——测试里那些"该报/不该报"的断言，全部跑在内存里的合成夹具上。

## 4. 数据流

```
                  ┌──────────────────────────────────────────────┐
   dataset/ ─────►│ scan(root)                                   │  只读，不做判断
   (用户的裸文件夹) │  → Dataset{images[], meta[], orphans[], notes[]}
                  └──────────────────────────────────────────────┘
                                    │
                    ┌───────────────┴────────────────┐
                    ▼                                ▼
        ┌───────────────────────┐      ┌──────────────────────────┐
        │ audit(ds) → [Finding] │      │ consensus_of(images)     │  纯函数，可单测
        │ 17 条规则             │      │  → TriggerConsensus      │
        └───────────────────────┘      └──────────────────────────┘
                    │                                │
                    └───────────────┬────────────────┘
                                    ▼
                  ┌──────────────────────────────────────────────┐
                  │ build_payload(...)                           │  每图算相对 src + findings 反查
                  └──────────────────────────────────────────────┘
                                    │
                                    ▼
                  ┌──────────────────────────────────────────────┐
                  │ render(...) → 单文件 HTML                     │  CSS/JS/JSON 内联
                  └──────────────────────────────────────────────┘
                                    │
                                    ▼
                  ┌──────────────────────────────────────────────┐
                  │ verify(html) → 不变量检查                     │  独立子命令，只看产物
                  └──────────────────────────────────────────────┘
```

每张图的三种 caption 来源是这套数据模型的核心区分：

| `cap_source` | 含义 | 规则后果 |
|---|---|---|
| `sidecar` | 同名 `.txt` 存在 | 正常；参与"重复"与"触发词漂移"判定 |
| `default` | 继承 `default_caption.txt` | `W004`：只有身份块、没有逐图变量 |
| `none` | 两者都没有 | `E001`：训练时要么被跳过、要么是噪声 |

## 5. 不变量与三层验证

### 5.1 受检的不变量

| # | 不变量 | 由谁保证 | 自动化 |
|---|---|---|---|
| I1 | 产物零远程资源 | `lora-audit verify` | ✅ |
| I2 | 产物零 ES Module（`file://` 下会被 CORS 拦掉） | `verify` | ✅ |
| I3 | 产物零运行时请求（`fetch` / `XMLHttpRequest`） | `verify` | ✅ |
| I4 | 内联数据块是合法 JSON，且每张图按相对路径可达 | `verify` | ✅ |
| I5 | 脚本运行时控制台零报错 | `browser_check` | ✅（需本机 Chrome） |
| I6 | 扫描跳过自己的产物目录 `_lora_audit/` | 单测 | ✅ |
| I7 | 干净数据集退出码 0（告警不是噪声） | 单测 | ✅ |
| I8 | 全仓只有 2 处写文件，且都在 `-o` 路径下 | 人工审查 | ⚠️ 未自动化 |

### 5.2 三层验证，以及它们各自**查不出**什么

| 层 | 命令 | 能证明 | **查不出** |
|---|---|---|---|
| 端到端 | `python3 -m unittest discover -s tests` | 规则命中、退出码、URL 编码、镜像 caption 树 | 真实渲染 |
| 产物不变量 | `lora-audit verify <html>` | 离线可用性、数据块合法性、图片可达 | **JS 报错、双重 URL 编码**、布局 |
| 真浏览器 | `node tools/browser_check.mjs <html>` | 渲染、抽屉、灯箱、筛选、搜索、主题、控制台 | 规则正确性 |

**这不是过度测试，是踩出来的。** 本仓库历史上真的漏过一次双重 URL 编码：Python 侧 `quote()` 编了一次，JS 侧又 `encodeURI()` 编了一次，带空格的文件名变成 `%2520` → 浏览器报 `ERR_FILE_NOT_FOUND`。而 `verify` **报的是 OK**——因为它只解码一次，路径仍然可达。**第 2 层结构上查不出第 3 层的问题。** 这就是 `browser_check.mjs` 不是可选项的原因。

同样的教训还有一条环境事实：本机 Chrome 153 下**直连 page 级 WebSocket 时 renderer 域命令不返回**（浏览器域正常），必须走 browser 级 + `Target.attachToTarget(flatten)` + `sessionId`；且它自带的 renderer 沙箱在受限进程环境里起不来（现象是"连接正常、事件能收、命令石沉大海"），需要 `--no-sandbox`。两条都写在脚本头部注释里。

## 6. 规则引擎的取舍

17 条规则：**1 错误 / 13 警告 / 3 信息**。

### 6.1 三级语义

| 级别 | 含义 | 退出码影响 |
|---|---|---|
| `error` | 训练**一定**出问题（图没有 caption） | 默认让退出码为 1 |
| `warn` | 很可能有问题，但可能是有意为之 | 只影响 `--strict` |
| `info` | 只是把识别到的事实说出来（布局、分组、推定触发词） | 不影响 |

### 6.2 "宁可少报也不误报"的具体做法

| 做法 | 例子 |
|---|---|
| **阈值不足时闭嘴** | `W003` 触发词漂移：样本 < 3 张、或主流触发词覆盖 < 60% 时**不报** |
| **让步式措辞，不硬判错** | `W008` 分辨率不统一会写"分桶训练本来就要求多样，如果这不是你有意为之……" |
| **只报能一眼验证的事** | 不猜意图、不评价画风、不判断"这张图好不好" |
| **区分事实与建议** | `scan` 只记录；判断集中在 `rules`；每条 `warn`/`error` 都带一个「怎么办」 |

### 6.3 规则的两个"现实世界"细节

**镜像 caption 树**（`cap_kohya/` 这类）：同一批图的**另一套** caption，天然没有同名图片。按"找不到同名图就判孤儿"会满屏误报——真实数据集首跑就报了 **47 个孤儿**。现在的判定是"路径不同但同名 → 另一套 caption profile"，并在报告的"识别到的布局"里说出来。

**条目类型 `kind`**：`W006`（孤儿 caption）与 `W010`（系统杂物）的条目是**路径不是图片**。早期版本给它们也渲染了"只看这 N 张"的筛图按钮，点了得到空网格。

## 7. 实测踩到的坑（都修了，列出来是为了不再犯）

| # | 现象 | 根因 | 只有谁能发现 |
|---|---|---|---|
| 1 | 真实数据集报 47 个孤儿 caption | 把 `cap_kohya/` 镜像树当成了孤儿 | 拿真实文件夹跑 |
| 2 | 带空格文件名永久破图（`ERR_FILE_NOT_FOUND`） | 双重 URL 编码（`%2520`） | **真浏览器**（`verify` 报 OK） |
| 3 | 14 条问题时图片区被推到 3000px 之下 | 问题卡单列排布 | 真浏览器（量首图偏移） |
| 4 | 路径类规则渲染出筛图按钮，点了空网格 | 没有区分条目类型 | 真浏览器（点一下） |
| 5 | 控制台一条 `ERR_FILE_NOT_FOUND` 噪声 | `file://` 页面缺 favicon | 真浏览器（读控制台） |
| 6 | 首屏看不到检查结果 / 区块文字互相压 | 区块高度写死 + 长文本不收缩 | 生成后目检 |
| 7 | **所有图都读不出尺寸**，`W007`/`W008` 变盲区 | 按**扩展名**分派图片解析器，而真实数据集里 `.png` 其实是 WebP | **拿真实第三方数据集跑** |
| 8 | `lora-audit scan --json - \| jq` 解析失败 | 人类可读摘要和 JSON 一起打到 stdout | 试图按 README 自己推荐的 CI 用法用它 |

## 8. 已知缺陷与代价（诚实清单）

1. **看图走原图，没有缩略图通道**。上千张的数据集首屏会慢。`pip install lora-audit[thumbs]` 这个 extras 已经在 `pyproject.toml` 里声明，但**通道没实现**。
2. **报告不能单独挪走**。图片是相对路径，报告与数据集必须保持相对位置；挪走后 `verify` 会报，页面会降级显示"图片读不出来（已被移动或删除）"。
3. **豁免机制只能按"规则"豁免，不能按"某几张图"豁免**。`W008` 那条噪声已由可选的 `.lora-audit-ignore` 解决（豁免 ≠ 隐藏：降级为 info、标题标注、理由原样展示，见 [INSTANCES](INSTANCES.md) 实例 01）；但如果你只想豁免"这 3 张图"，目前做不到——只能整条规则豁免。
4. **只审图片**。视频、音频、以及任何非图像资产都不在扫描范围。
5. **触发词判定偏保守**：只取 caption 首词；需要 ≥3 张且覆盖 ≥60% 才敢报漂移；不支持多触发词。
6. **`W012`（val 未分层）只在数据集自带 `val.txt` 时才有意义**，没有清单就完全不出声。
7. **分批渲染的阈值（>400 张）是拍的**，没有实测依据。
8. **只在 1 个真实第三方公开数据集上验证过**（9 张、零 caption、`.png` 实为 WebP），加上 15 个按训练器官方约定构造的布局夹具。**还没经受「大量真实目录」的考验**——如果你手上的目录扫出来不对，请开 issue：[模板](../.github/ISSUE_TEMPLATE/bug-report.yml)要的是目录树 + caption 原文，不需要图片。

## 10. 怎么验证本文档说的都是真的

```bash
git clone <repo> && cd lora-audit

python3 -m unittest discover -s tests -v     # 35 个用例（纯标准库）
python3 examples/make_example.py             # 造一份带 6 类已知缺陷的数据集
python3 -m lora_audit scan examples/demo-dataset --open
python3 -m lora_audit verify examples/demo-dataset/_lora_audit/report.html

node tools/browser_check.mjs examples/demo-dataset/_lora_audit/report.html --shot out.png
```

最后一条需要本机有 Chrome/Chromium；没有会**跳过**（退出码 0），不让它成为贡献者的门槛。
